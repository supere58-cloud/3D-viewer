# Mine Viewer

Offline 3D viewer for mine models on Android phones and tablets, and on iPad
from the same code. Opens Micromine DXF exports (wireframes, strings, drillhole
traces) plus GLB, OBJ and STL. Nothing is uploaded: the app makes no network
requests at all.

- TypeScript + Vite + three.js + three-mesh-bvh, packaged with Capacitor 8.
- The same `dist/` runs as an installable offline PWA (for iPad without an
  Apple developer account).
- UI in Russian (default) and English.

> **Status.** Everything below was built and tested in a Linux container with
> headless Chromium. It has **not** been run on a physical phone or tablet, the
> Android and iOS projects have **not** been compiled, and the parser has only
> seen synthetic DXF. Read [What was not verified](#what-was-not-verified)
> before relying on it in the field.

## Using the app

| Action | Gesture |
|---|---|
| Orbit | one finger drag |
| Zoom / pan | two fingers pinch / drag |
| Measure | tap a point; tap a second point for distances |
| Plan view, north up | **План** button, or tap the north arrow |
| Layers, files, diagnostics, settings | bottom sheet (phone) or side panel (tablet) |

Mouse: left drag orbits, right drag or Shift+drag pans, wheel zooms.

- **Open files**: the Open button (several files at once), "Open with" / Share
  from a file manager or messenger (Android and iOS apps), or drag and drop in a
  desktop browser.
- **Measurement**: a tap snaps to the nearest vertex when one is within about a
  finger width, otherwise to the surface or line under the finger. It shows
  true X / Y / Z to two decimals, the layer and the source file. A second tap
  adds 3D distance, horizontal distance, ΔZ, azimuth (clockwise from north) and
  dip (negative = downwards). **Копировать** copies it all as text.
- **Layers**: grouped by file; eye = visibility, swatch = colour, the percent
  button cycles opacity 100 / 50 / 20 %. Settings are remembered per file
  (file name + size).
- **Recent files**: opened files are copied into the app's private storage so
  they reopen offline. Switch this off in Settings if copies must not be kept.
- **Diagnostics tab**: per file — format, DXF version, detected encoding,
  entity counts by type, what was skipped and why, bounding box, warnings.
  "Copy report" gives plain text you can send to whoever maintains the app.

## Assumptions

Tell me if any of these is wrong; each is a one-line change.

- Units are metres. DXF, OBJ and STL are Z-up in real-world coordinates.
  GLB is Y-up (glTF standard) and is converted to Z-up.
- DXF without a usable `$DWGCODEPAGE` and with non-UTF-8 text is Windows-1251.
- App name "Mine Viewer", application id `com.mineviewer.app` (placeholders:
  change in `capacitor.config.ts`, `android/app/build.gradle`,
  `android/app/src/main/res/values/strings.xml` and the Xcode project; the Java
  package directory has to be renamed to match).
- ACI colour 7 is drawn white (dark background).

## Develop and test

Requires Node.js 22+.

```bash
npm ci
npm run dev        # dev server with hot reload (no CSP, no service worker)
npm test           # unit tests: parser, encodings, measurement, picking, strings
npm run build      # type-check + production build into dist/
npm run preview    # serve dist/ locally
```

Extra checks (need Playwright with Chromium installed on the machine; it is
deliberately not a project dependency):

```bash
npm run e2e                      # browser smoke test against dist/, screenshots in e2e-out/
node scripts/stress.mjs <dir>    # 100 MB DXF and 2M-triangle STL; writes ~200 MB into <dir>
npm run bench -- 100             # parser throughput on a synthetic 100 MB DXF (Node)
```

Fixtures and the demo model are generated by scripts and committed:
`npm run fixtures`, `node scripts/make-sample.mjs` (`samples/demo-mine.dxf`,
synthetic, Windows-1251), `node scripts/make-icons.mjs`.

## Android: debug APK

Requirements: Node.js 22+, **JDK 21**, Android SDK with platform **API 36** and
build-tools (install Android Studio, or the command-line tools and
`sdkmanager "platforms;android-36" "build-tools;36.0.0" "platform-tools"`).
`ANDROID_HOME` must point at the SDK.

```bash
npm ci
npm run android:debug
# = npm run build && npx cap sync && cd android && ./gradlew assembleDebug
```

The APK is `android/app/build/outputs/apk/debug/app-debug.apk`. Install it:

```bash
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
```

Without a local SDK: every push runs `.github/workflows/build.yml`, which builds
the same debug APK and attaches it to the workflow run as the artifact
`mine-viewer-debug-apk`.

Minimum Android 8.0 (API 26). The "Android System WebView" (or Chrome) on the
device must be reasonably current (roughly version 90 or newer); on Android 8
update it from the Play Store, or from an APK if the device has no Play Store.

## Android: signed release

1. Create a keystore once and keep it safe. Losing it means you cannot update
   the installed app.

   ```bash
   keytool -genkeypair -v -keystore mine-viewer-release.jks \
     -alias mine-viewer -keyalg RSA -keysize 4096 -validity 10000
   ```

2. Put the keystore in the repository root (it is git-ignored) and create
   `android/keystore.properties` from `android/keystore.properties.example`:

   ```properties
   storeFile=../mine-viewer-release.jks
   storePassword=...
   keyAlias=mine-viewer
   keyPassword=...
   ```

   `storeFile` is relative to the `android/` directory.

3. Raise `versionCode` (and `versionName`) in `android/app/build.gradle`.

4. Build:

   ```bash
   npm run android:release
   ```

   Outputs: `android/app/build/outputs/apk/release/app-release.apk` (for
   side-loading / MDM) and `android/app/build/outputs/bundle/release/app-release.aab`
   (for Google Play). Without `keystore.properties` the build produces an
   unsigned `app-release-unsigned.apk`.

5. Check the signature and that the app really has no network permission:

   ```bash
   $ANDROID_HOME/build-tools/36.0.0/apksigner verify --print-certs android/app/build/outputs/apk/release/app-release.apk
   $ANDROID_HOME/build-tools/36.0.0/aapt2 dump permissions android/app/build/outputs/apk/release/app-release.apk
   ```

   The second command must not list `android.permission.INTERNET`.

## iOS / iPadOS build

Requires a Mac with Xcode 16+ and Node.js 22+. Dependencies come through Swift
Package Manager; there is no CocoaPods step.

```bash
npm ci
npm run cap:sync
npx cap open ios
```

In Xcode: select the **App** target → *Signing & Capabilities* → choose your
team (a free personal team works for installing on your own iPad for 7 days; a
paid developer account is needed for TestFlight, ad hoc or enterprise
distribution). Pick the iPad as destination and press Run. For distribution use
*Product → Archive*.

Deployment target is iPadOS / iOS 16.0. `Info.plist` registers the app for
`.dxf`, `.glb`, `.obj` and `.stl`, so it appears under "Open in…" and Share in
Files and in messengers.

## PWA deploy

`npm run build` produces a static site in `dist/`. Host it on any HTTPS server
(a service worker requires HTTPS; `localhost` is the only exception). An
intranet server is fine and keeps even the app download inside the company.

- Paths are relative, so `dist/` can live in a sub-folder.
- Serve `index.html` and `sw.js` with `Cache-Control: no-cache` so updates are
  picked up; everything under `assets/` is content-hashed and can be cached
  forever.
- Send the Content-Security-Policy as a response header as well as the built-in
  `<meta>` tag. `dist/_headers` does this on Netlify and Cloudflare Pages. For
  nginx:

  ```nginx
  location / {
    root /var/www/mine-viewer;
    add_header Content-Security-Policy "default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' data: blob:; font-src 'self'; worker-src 'self'; manifest-src 'self'; connect-src 'none'; base-uri 'none'; form-action 'none'; object-src 'none'; frame-ancestors 'none'" always;
    add_header Referrer-Policy "no-referrer" always;
    add_header X-Content-Type-Options "nosniff" always;
    location = /sw.js      { add_header Cache-Control "no-cache"; }
    location = /index.html { add_header Cache-Control "no-cache"; }
  }
  ```

  (nginx drops inherited `add_header` lines inside a nested `location`; repeat
  the security headers there or use an `include` file.)

**Install on iPad:** open the URL in Safari while online once → Share → *Add to
Home Screen*. After that it starts and opens files with no connection. Files
are opened with the in-app Open button; an installed PWA on iPadOS cannot
register for "Open in…" (that needs the native build).

**Install on Android (alternative to the APK):** open the URL in Chrome → menu →
*Install app*.

## How it works

```
src/core/            format code, no DOM, runs in the worker and in Node tests
  lines.ts           byte-level line splitter, exact float64 number parser
  dxf/parser.ts      streaming DXF state machine, blocks, polylines, OCS
  dxf/encoding.ts    UTF-8 / code page detection, \U+XXXX, MTEXT, %%c %%d %%p
  dxf/aci.ts         AutoCAD colour index table
  formats/           OBJ, STL (ASCII + binary), GLB readers
  model/builder.ts   per-layer buffers, tiled origins, colours
  load.ts            format detection, diagnostics
src/worker/          parse worker: read, parse, build BVH, transfer
src/viewer/          camera + gestures, scene, grid, labels, picking
src/ui/              app shell, panel, measurement card
src/platform/        storage, worker launcher, Capacitor bridge
src/i18n/            ru.json, en.json — every UI string
android/, ios/       Capacitor projects (android has the FileIntake plugin)
```

**Precision.** DXF numbers are parsed to float64 exactly. Geometry is binned
into 16 km tiles while streaming and stored as float32 offsets from the tile
centre; at the end the tile holding most of the model defines one float64
origin per file. The GPU only ever sees small numbers relative to the camera,
so there is no jitter, and reported coordinates are origin + offset (error
below 1 mm within about 25 km of the model centre). A stray entity near 0,0
does not spoil this; it is reported as a warning and ignored when framing.

**Streaming.** The file is read in 4 MB chunks in a Web Worker and never held
as one string. Cancel terminates the worker. Peak memory is roughly the final
geometry (36 bytes per triangle) plus the BVH.

**Rendering.** One mesh, one line set and one point set per layer, so draw
calls scale with layers, not entities. Frames are drawn only when something
changes. If frames get slow while a finger is down, the resolution drops for
the duration of the gesture.

**Picking.** Surfaces through a three-mesh-bvh tree built in the worker; lines
and points by a screen-space scan (about 10 ms per million segments, only on
tap). Lines hidden behind a surface are not picked.

**No network.** Three layers: (1) CSP `default-src 'none'; connect-src 'none'`
in every production build; (2) no code path uses `fetch`/XHR — files come from
the picker or over the Capacitor bridge; (3) the Android manifest does not
request `INTERNET`, so the OS refuses sockets regardless. There are no
analytics and no third-party scripts; all dependencies are bundled.

**DXF coverage.** 3DFACE, LINE, POLYLINE (3D, 2D, polyface mesh, polygon mesh),
LWPOLYLINE with elevation, POINT, TEXT, MTEXT, ATTRIB, INSERT (nested, scale,
rotation, arrays, layer 0 / BYBLOCK inheritance), plus SOLID, TRACE, CIRCLE and
ARC. Everything else is skipped and counted in Diagnostics. Colours: ACI on the
entity, BYLAYER through the LAYER table, true colour (420). Layers that are off
or frozen in the file start hidden.

## What was not verified

Honest list. None of this has been tried; each item is a thing to check on
first contact with real hardware and real data.

**Real devices**
- The app has never run on a physical Android phone, tablet or iPad.
- Frame rate. The ≥ 30 fps target with 2 million triangles on a mid-range phone
  is unmeasured; the container has no GPU. Memory on a 4 GB phone is estimated
  (about 130 MB for 2 M triangles), not measured.
- Touch gestures were driven with synthetic touch events in desktop Chromium,
  not with fingers. Sunlight readability and touch-target comfort are untested.
- WebGL context loss and app pause / resume are handled in code but were never
  triggered for real.

**Android**
- `android/` was never compiled: the container cannot download the Android SDK.
  The custom Java plugin was type-checked against the Android 14 API with
  stand-in Capacitor classes, which is weaker than a real build. The GitHub
  Actions workflow is the first real compile.
- That the WebView loads the app **without the `INTERNET` permission**. This is
  expected to work because Capacitor serves assets by intercepting requests,
  but it is unproven. If the app shows a blank or error page on launch, remove
  the `INTERNET` line with `tools:node="remove"` from
  `android/app/src/main/AndroidManifest.xml`, add
  `<uses-permission android:name="android.permission.INTERNET" />`, rebuild, and
  tell me — the CSP still blocks network use from the page.
- "Open with" / Share from specific apps (Files, Telegram, WhatsApp, Total
  Commander…). Which apps offer Mine Viewer depends on the MIME type they
  attach to a `.dxf`; the manifest lists the common ones and
  `application/octet-stream`.
- Reading large shared files through the bridge (base64 chunks): speed and
  memory for a 100 MB file are unmeasured.

**iOS / iPadOS**
- `ios/` was generated on Linux and never opened in Xcode or compiled.
- The document-type registration and the file hand-off (`appUrlOpen` →
  Filesystem plugin) are untested.
- The PWA was tested in Chromium only, not in Safari. In particular, private
  storage for recent files uses `createSyncAccessHandle` in a worker (Safari
  15.2+); if it is unavailable the app still works but recents need re-picking.

**Data**
- No real Micromine export has been parsed. All DXF fixtures are synthetic,
  written by `scripts/make-fixtures.mjs` to my reading of the DXF reference.
  Please open a few real exports and send the Diagnostics report for any that
  look wrong or list skipped entities.
- The original HTML prototype was not available to me (the attachment did not
  arrive), so behaviour was built from the written spec, not compared with it.

**What was verified here**
- 45 unit tests (parser fixtures: CP1251, UTF-8, polyface mesh, polygon mesh,
  large coordinates, truncated file at every offset, blocks, binary DXF,
  OBJ / STL / GLB; measurement maths; picking; string resources).
- Browser smoke test in headless Chromium with phone and tablet profiles:
  open, orbit, pinch, tap-measure, surface and line picking, layers,
  diagnostics, language switch, recents surviving reload, four formats at once,
  start and open a file with the network switched off, and that an outside
  `fetch()` is refused by the CSP. No request left the origin.
- A 102 MB DXF (470 000 triangles) loads in about 2 s and a 2 000 000-triangle
  STL in about 1.5 s on the container's desktop CPU, with picking in 1–2 ms.

## Known limits

- Binary DXF and DWG are not supported (binary DXF is detected and explained).
- Polyline bulges (arc segments) are drawn straight; SPLINE, ELLIPSE, HATCH,
  DIMENSION, 3DSOLID and MESH are skipped and counted.
- DXF text is drawn as upright screen labels; rotation, justification and
  fonts are ignored. At most 500 labels are drawn at once (the largest ones).
- GLB: geometry and base colour only; no textures, no Draco / Meshopt.
- Binary STL and GLB store float32, so 7-digit coordinates in those formats are
  already rounded in the file (about 0.5 m at 7 000 000). Use DXF or OBJ for
  real-world coordinates.
- Geometry further than about 65 km from the main model in the same file loses
  precision and is flagged in Diagnostics.
- Transparent layers are not depth-sorted per triangle.
- Layer settings are keyed by file name and size; a re-export of the same size
  and name inherits them.
